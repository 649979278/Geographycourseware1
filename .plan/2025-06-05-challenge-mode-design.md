# 闯关模式设计文档

## 1. 概述

在现有中国地形教学课件的 `terrain.html` 页面中，新增**闯关模式**。该模式与现有单人练习、双人PK并列，作为第三种游戏模式。

### 核心规则
- 从所有已维护采集点（山脉 + 线型 + 地形区）中**随机抽取**组成关卡
- **不区分**山脉或地形区类型，只按难度星级分关
- 每关至少3题，最多8题；最少2关，最多10关
- 难度**逐级递增**：低星题目放在前置关卡，高星题目放在后置关卡
- 每关内部题目**随机洗牌**
- 答错**一题即闯关失败**，必须从头再来
- 每闯过一关，自动获得 **1 次目标提示**（初始 0 次）
- 闯关模式可以开启图层按钮下的所有功能，但**没有目标提示开关**

## 2. 数据模型变更

### 2.1 采集点新增字段

每个采集点数据新增 `difficulty` 字段：

```js
{
  id: "qinling",
  name: "秦岭",
  difficulty: 1,        // 新增：1 | 2 | 3，默认 1
  targetLevel: "mountains",
  // ... 其他字段不变
}
```

### 2.2 向后兼容

- 现有数据文件（`mountains.js`、`lines.js`、`terrain-regions.js`）中未包含 `difficulty` 字段的采集点，加载时默认赋值为 `1`
- 编辑器导出时始终写入 `difficulty` 字段

### 2.3 编辑器UI

## 3. 关卡生成算法

### 3.1 输入

全部采集点（`mountains` + `lines` + `regions`），每个点带有 `difficulty`（1~3）。

### 3.2 算法步骤

1. **读取全部采集点**，按 `difficulty` 分三组
2. **计算关卡数**：
   - 总题数 = 采集点总数
   - 初步关卡数 = `Math.ceil(总题数 / 5)`
   -  Clamp 到 `[2, 10]` 范围
   - 若 `总题数 / 关卡数 < 3`，则降低关卡数，确保每关至少 3 题
   - 最终关卡数 = `Math.min(10, Math.max(2, Math.floor(总题数 / 3)))`
   - 重新计算每关题数：`每关题数 = Math.ceil(总题数 / 关卡数)`，最后一关取余数
3. **按难度分配到关卡**（核心原则：低星前置，高星后置）
   - 将所有采集点按 `difficulty` 升序排列
   - 依次向各关卡填充：第1关先填满，再填第2关，依此类推
   - 由于已按难度升序排列，自然实现低星在前、高星在后
   - 每关填充完毕后，将该关的 `items` 做一次 `shuffleArray` 随机洗牌
4. **输出**：关卡数组

### 3.3 边界示例

| 采集点分布 | 总题数 | 关卡数 | 每关分配 |
|---|---|---|---|
| 5个1星 + 3个2星 + 2个3星 | 10 | 2 | 第1关：5个1星 + 1个2星（6题）<br>第2关：2个2星 + 2个3星（4题） |
| 3个1星 + 2个2星 + 1个3星 | 6 | 2 | 第1关：3个1星 + 1个2星（4题）<br>第2关：1个2星 + 1个3星（2题 → 修正为每关3题） |
| 20个混合 | 20 | 4 | 每关5题 |
| 9个混合 | 9 | 3 | 每关3题 |

### 3.4 数据结构

```js
state.challenge = {
  active: false,           // 是否处于闯关模式
  totalLevels: 0,          // 总关卡数
  currentLevelIdx: 0,      // 当前关卡索引（0-based）
  currentQuestionIdx: 0,   // 当前关卡内已答题数（0-based，用于失败提示）
  levels: [                // 预生成的关卡数组
    { items: [...], levelNumber: 1 },
    { items: [...], levelNumber: 2 },
    // ...
  ],
  hintsAvailable: 0,       // 当前可用提示次数
  playerName: '',          // 挑战者姓名
  totalScore: 0,           // 累计得分
  totalTimer: 0            // 累计计时（秒）
};
```

## 4. 游戏流程

### 4.1 进入闯关模式

1. 用户点击模式切换栏的"闯关模式"按钮
2. `state.mode = 'challenge'`
3. 调用 `enterChallengeMode()`：
   - 隐藏单人/PK相关的UI元素
   - 显示闯关模式专属开始界面
   - 调用 `generateLevels()` 生成关卡数据
   - 重置 `state.challenge` 状态

### 4.2 开始界面

复用现有的 `#startOverlay`，内容调整为：
- 标题："闯关模式"
- 描述："共 N 关，答错一题即失败，闯过一关获得 1 次提示！"
- 隐藏关卡选择卡片（闯关模式不区分山脉/地形区）
- 显示单人姓名输入框
- "开始挑战"按钮

### 4.3 关卡进行中

1. 根据 `currentLevelIdx` 加载当前关的 `items` 到 `state.items`
2. 复用现有 `setupLevel()` 的核心逻辑渲染地图标记和侧边栏标签
3. 玩家拖拽作答：
   - **答对**：复用 `handleCorrect()`，更新本关进度
   - **答错**：复用 `handleWrong()`，但逻辑变为**直接触发闯关失败**，不再扣分或允许继续
4. 每答完一题，`currentQuestionIdx++`
5. 本关全部答完 → 触发**关卡通过**

### 4.4 关卡通过

1. `hintsAvailable++`
2. `currentLevelIdx++`
3. 显示短暂浮层提示（Toast）："第 X 关通过！获得 1 次提示"（1秒）
4. 自动加载下一关：
   - 若还有下一关 → 重新渲染该关题目
   - 若已是最后一关 → 触发**闯关成功**

### 4.5 闯关成功

调用 `showChallengeSuccess()`：
- 弹窗标题："🎉 闯关成功！"
- 显示总用时、总得分
- 显示闯过的总关卡数
- 按钮："再玩一次"、"返回首页"

### 4.6 闯关失败

调用 `showChallengeFail()`：
- 弹窗标题："💔 闯关失败"
- 显示："你在第 X 关第 Y 题答错了"
- 显示已通过的关卡数
- 按钮："重新挑战"（从头生成新关卡）、"返回首页"

### 4.7 提示功能

- 闯关模式下**不显示**"目标提示"图层开关
- 提示按钮显示可用次数：`💡 提示 (<span>{hintsAvailable}</span>)`
- 每次使用提示消耗 1 次可用次数（不扣分）
- 提示逻辑复用现有 `useHint()`，但改为从 `hintsAvailable` 扣减而非从得分扣减

```
                                            [闯关失败]          [关卡通过]
                                                  |                |

                                                  |           v        v

```

## 7. 边界情况处理

| 场景 | 处理方式 |
|---|---|
| 采集点总数 < 6（无法形成2关每关3题） | 仍按规则生成2关，分配尽量均匀 |
| 采集点总数 > 80（超过10关 × 8题） | 关卡数封顶10关，每关题数 = ceil(总数/10)，最多每关8题，多余题目截断不进入闯关 |
| 某星级题目数为0 | 跳过该星级，按实际有的星级分配 |
| 所有采集点都是同一星级 | 均匀分配到各关，每关内部随机 |
| 用户未维护任何采集点 | 开始按钮禁用，提示"暂无采集数据" |
| 只剩1个采集点 | 按最小规则生成2关无法满足，此时特殊处理为1关1题（兜底） |
